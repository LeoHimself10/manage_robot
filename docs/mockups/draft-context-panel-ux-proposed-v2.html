草案侧栏布局 v2（拟）

在 v1 基础上进一步收敛视觉噪音：去掉序号/check 符号、用指派进度条 + 负责人头像表达状态，底栏主按钮更明确。交互仍为「编辑表格 + 双 Popup 发放」，不改 API。

💡
v1 仍显「丑」的原因：摘要 chip、序号方块、✓ 符号叠在一起仍像临时拼装；顶部分割线 + 底部分割线把 280px 切成四段。v2 改为一条顶色带 + 一块可滚动列表 + 固定底栏，统计信息用细进度条，列表用状态点 + 负责人圆头像，减少边框与标签数量。

二、v1 → v2 关键变化

v1 拟改（仍偏碎）

  • 摘要行 + chip 标签，信息重复
  • 序号方块 + ✓ 符号，像 checklist 而非任务板
  • 头/摘要/列表/底栏 四道横线切分
  • 「编辑表格」文字链与标题抢视线

v2 拟改（推荐）

  • 顶色带：绿=可发、橙=有缺口，一眼看状态
  • 进度条替代统计卡片与 chip
  • 负责人头像替代「已指派」文字
  • 全宽「编辑草案表格」：摘要下方独立 secondary 按钮，带表格图标
  • 列表仅细分隔线，无额外灰框

三、信息架构（不变的业务逻辑）

区域内容来源交互
标题 + 数量徽章 computeDraftSummary().count —
指派进度 count − unassigned / count 未指派 > 0 时顶色带与进度条为 warn 色
最近截止 draftStatDue，格式 yyyy-MM-dd 无截止时隐藏该行
子任务行 preview 列表 + assignment 映射 有 assignee 显示姓氏头像；无则「?」+ 待指派
编辑表格 — 摘要区下方全宽 secondary 按钮，打开现有 Excel 弹窗（openDraftEditor）
底栏 — 「发放任务」→ 现有双 Popup + agent 消息；空态隐藏底栏与编辑按钮

四、实现注意（后续改代码时）

  • 侧栏宽度仍约 260–280px；头像可用姓氏首字，颜色可按 userId hash 固定
  • 长标题保持 2 行截断；列表区域 max-height + 滚动，底栏 sticky
  • 移动端侧栏在聊天下方时，底栏按钮仍全宽；顶色带与进度条保留
  • 动文件：manager-workbench-pages.ts（DOM + updateDraftContext）、workbench-app-styles.ts（新 class 替换 draft-stat-*）
