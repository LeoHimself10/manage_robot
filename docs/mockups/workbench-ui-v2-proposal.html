工作台整体 UI · 诊断与改造方向

基于现有 workbench-app-styles.ts + 员工/主管/Admin/登录页的实现。结论：不是「缺组件」，而是缺少统一产品壳、视觉层级和 DingTalk 场景适配——像内部工具原型，不像可交付的企业工作台。

核心诊断：丑在哪（6 条）

不是单一页面问题，是全局设计语言缺失。

  • 1. 没有「应用壳」每页各自为战：顶栏 + 一堆 pill + 退出，像网页合集，不像一个 App。
  • 2. 导航形态过时5～6 个圆角 pill 横排；小屏等分后像按钮墙，主次不清。
  • 3. 视觉层级扁平灰底 + 白 card + 浅蓝 active，全是同一权重；KPI、筛选、卡片、提示条长一个样。
  • 4. 信息密度失控任务卡片塞 6+ 规划字段 + 多按钮；主管页 KPI×5 + 筛选×6 格，首屏像 Excel。
  • 5. 风格分裂工作台 SSR 一套 CSS；外部登录/站点首页/钉钉登录页各写各的 inline style，像三个产品拼盘。
  • 6. 「工程文档感」landing 页是路径列表 README；brand 用 UPPERCASE 英文「员工工作台」，缺少品牌与角色感。

分区改造要点（不改业务，只改呈现）

员工端

  • 导航 Tab 过多；待承接/进行中/画像/安全平级竞争
  • 卡片 接受/拒绝/协助按钮同级，缺「主行动」强调
  • 可做 卡片分「摘要区 + 折叠规划区」；状态色 + 文字标签

主管端

  • KPI 5 块数字墙；与下方表格信息重复
  • 筛选 6 格表单像后台 CRUD，不像「待办 inbox」
  • 可做 默认「待您处理」视图；KPI 缩为 2～3 个 + 其余进摘要

登录 & 入口

  • 分裂 钉钉免登 / 外部登录 / 首页三套 UI
  • 首页 纯文档列表，无产品感
  • 可做 统一 Login Shell + 角色分流卡片

推荐改造路线（只规划，不动代码）

假设选 方向 A 或 B，分 4 步滚动交付，每步可独立上线。

Step 0 · 设计系统基线（1～2 天）

产出 Figma/HTML token 页，不碰业务逻辑

  • 统一色板、圆角、阴影、字号阶梯（替换散落 inline style）
  • 组件清单：AppShell、SegNav、KpiStrip、TaskCard、StatusBadge、EmptyState、Banner
  • 状态色规范：待处理 / 进行中 / 阻塞 / 完成（色+文字，不单靠颜色）

Step 1 · 壳层 + 导航（2～3 天）

  • 抽 renderWorkbenchShell()：侧栏或顶栏 SegNav，员工/主管/Admin 共用
  • 员工端：合并「能力画像 + 账号安全」→「我的」（你之前 9A 方案，仍建议做）
  • 登录页 / 首页纳入同一 Shell

Step 2 · 任务卡片 & 列表 inbox 化（3～4 天）

  • TaskCard v2：首屏仅 标题 + 状态 + 负责人 + 截止 + 主按钮
  • 规划 6 项 + 更多规划 → <details> 或「查看要点」抽屉
  • 主管列表：默认筛「待您处理」；KPI 从 5 减到 3

Step 3 · polish + 移动端（2 天）

  • 空状态插画/文案；加载 skeleton 统一
  • 钉钉 webview 安全区、字体缩放、触控热区 ≥ 44px
  • 外部执行者页保持同一 token，仅文案区分
