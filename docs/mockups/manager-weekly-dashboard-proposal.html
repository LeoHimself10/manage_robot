设计说明 · 最佳实践与实现要点（给研发）

1. 信息架构（三层）

周摘要 KPI → 时间轴（任务×周 / 可选人员×周） → 双维明细表（任务展开子任务 / 人员卡片列子任务）+ 事件 feed。主管开会路径：KPI → 时间轴看冲突 → 切人员维度问负载 → 切任务维度过 WBS。

2. 时间维度

默认 ISO 自然周（Asia/Shanghai，周一 00:00 起），与现有 PROGRESS_DIGEST_TIMEZONE、截止日 18:00 语义一致。支持：上一周/本周/近 N 周/自定义区间；时间轴左右各扩展 N 周展示历史事件条与未来 due_at 计划条（未来不用 LLM 猜，只读截止与状态）。

3. 数据来源（复用现网，不另造状态）

  • 正式任务 / 子任务：workbench-formal-task-store
  • 本周动态：task_events（已有 SUBTASK_PROGRESS / ACCEPT / BLOCK 等）
  • 聚合逻辑：复用 workbench-attention、progress-digest-facts，新增 GET /api/workbench/manager/weekly-dashboard?week=2026-W21&span=3

4. 双维聚合

按任务：顶层 task → 子任务行 → 列「本周进展」（事件摘要）+「下周」（due 落在 T+7 或计划状态）。按人员：assignee 分组 → 嵌套其负责的子任务；附带负载指标（进行中数、下周到期数、阻塞数）。两视图同一 API，groupBy=task|person。

5. 周度建议助手（新机器人能力）

建议不要塞进编排主链路，而是：

  • Backend：buildWeeklyReviewFacts() 输出结构化 facts（与 progress digest 同模式）
  • LLM：仅生成「必谈 / 关注 / 表扬 / 议程 / 负载建议」，禁止输出未在 facts 中出现的任务号或数字
  • 触发：① 定时周五 17:00；② Dashboard 按钮；③ 钉钉对话 WEEKLY_REVIEW 模式（QUERY 子集）
  • 落点：右侧栏 + 可选推送 Markdown 到主管单聊/群

6. 与现有能力关系

每日进展推送 = 日粒度收件箱；本 Dashboard = 周粒度指挥舱；历史任务页 = 操作台（改派/催办）。三处共用 SQLite 权威源，避免双写。

7. 分期建议

P0：周 API + Dashboard 页（任务/人员双视图 + 事件 feed）。P1：时间轴 ±N 周 + 未来 due 预览。P2：周度建议助手 + 定时推送 + 钉钉 QUERY。P3：导出会议议程 PDF / 与日历集成。
