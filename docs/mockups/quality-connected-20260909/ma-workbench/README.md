## 当前确认的流程

1. **全部事件**接收员工提交的 OA 记录，不等待 OA 审批通过。未确认选入的记录不会进入待我研判。
2. 点击事件，在该行正下方展开详细表单、OA 附件、审批与版本。只有一个业务按钮：**进入质量事件**；这里没有人工研判表单或后续流程导航。
3. 点击按钮后核对确认框。取消不改变状态；确认后加入**待我研判**并打开该队列。重复进入同一事件不重复入队。
4. 从队列打开事件，进入 **AI 与人工研判**。主动运行 AI 演示，查看两级分类、风险、依据、相似案例、信息缺口及来源版本。
5. **直接采纳 / 修改后采纳 / 否决并自行判断**。人工内容独立填写；调整分类、风险或结论会识别差异并要求修正原因。可不运行 AI 而直接人工研判。
6. **保存研判**仅新增人工版本，仍留在待我研判；不会推送初析。修改保存后的内容，必须重新保存才可确认。
7. 已保存研判结论后，点击 **确认并推送质量初析**，再次核对再确认。确认后移入跟踪处理中，等待佟成初析。研判区不再重复选择处理方式。

确认“进入质量事件”后，该记录进入质量事件的待研判环节。按用户最新要求，AI 区去掉“建议处理方式”，人工区去掉“处理方式”，不再提供普通反馈 / 待补资料 / 质量异常的分流选择。研判只确认分类、风险、事实摘要和结论，随后统一推送佟成初析。保存与推送仍然分开，旧演示记录的普通反馈、待补资料结果保留只读历史。

## 单部门流程校正

按用户确认：一个质量事件只推送给一个主责部门，不能由质量初析直接同时分配给多个部门。现有源码也要求 primaryDepartmentId 唯一，并通过部门目录解析唯一有效主管。确认初析后，将成果要求推入该主管的原任务规划入口，由其规划、分配和发布。

当前原型链路：马荣鑫研判 → 佟成初析并确认唯一主责部门 → 推送对应部门主管 → 主管在原任务系统分配本部门员工 → 员工提交结果 → 同一部门主管逐项及整体验收 → 佟成质量终验。

依据：.worktrees/yesterday-admin-test-actors/src/quality/analysis/quality-analysis-service.ts 的 confirmAnalysis 中唯一主责部门校验、resolveManager、stagePlanningThread，以及 src/web/quality-tracking-page.ts 的初析确认推送交互。仅核对源码，未改动正式实现。

已统一初析 V1/V2、部门接收记录、任务人员归属、主管验收、质量退回说明和公开动态。此前多部门原型已归档至 revisions/before-single-department/；四项模拟任务仍可用于比较不同员工状态。

## 新增：完整后续流程模拟数据

当前用户打开的 a8“图像导出时间较长”已调整为完整质量事件演示，默认展示已关闭结果。原 OA 表单与日志继续保留；此前普通反馈样例的原型文件归档于 revisions/before-flow-examples/。所有新结果均为预设模拟数据。

- 佟成初析：导出性能分析 V1/V2、修订原因、依据、信息缺口、部门建议及处理要求。
- 主管分配：一个主责部门（软件研发部）、一个对应部门主管（程远）；主管在原任务系统规划并分配四项任务给本部门员工。
- 员工承办：性能定位、导出优化、回归验证、使用场景复核四项结果；展开可看进度、主管意见、V1/V2 证据与完整时间记录。
- 质量终验：核对项、原因与措施、容量对照数据、逐项主管验收、关闭结论或指定节点退回。

事件顶部提供五种演示状态：已分配 / 待承接、执行与退回、待质量终验、终验退回、完整结果 / 已关闭。切换仅替换模拟状态，不代替主管、员工或质量人员执行实际业务操作。每种状态保留相应前序事实；未发生的承接与验收不显示为已完成。初析、分配与员工承办仍由同一事件关联。

“任务分配”和“员工承办”阶段进入不同子视图：主管分配表、员工承办结果。点击分配表中的承办结果，可直接展开相应任务。其他未完成事件提供“查看完整流程样例”，无需改变该记录的真实演示进度。

## 后续流程与导航

后续处理继续提供佟成初析 V1/V2、主管分配结果、员工承接与自报进度、提交完成、主管退回或验收、证据版本、质量终验与动态。马荣鑫在这些环节查看结果，不代替其他人员处理任务。

流程条在事件的各页签中保持挂载；点击只替换下方内容，浏览阶段不推进业务状态。返回列表恢复来源范围、搜索、筛选与页码；待我研判中已正式确认的记录会移出队列。浏览器前进后退可以回到事件。

未选入记录的直接事件链接会退回来源详情。已选入的记录再次进入会打开当前研判或处理记录，不再次入队。刷新将恢复初始演示数据，当前会话中新增的选入/研判不会持久保存。
