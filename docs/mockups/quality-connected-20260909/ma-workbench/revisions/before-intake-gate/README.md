## 设计范围

马荣鑫可在全部接入反馈中搜索 OA 编号、事件编号、尾号或关键词；同一时刻只在所选行下方展开一条来源反馈。列表单独显示 OA 审批状态、马荣鑫的研判状态和当前处理环节。

页面分两层，入口顺序为：**全部反馈 → 查找记录 / 查看来源资料 → 点击“进入质量事件” → 查看后续流程**。

- 反馈层只展示 OA 原始资料和我的研判，不展示后续流程条。已关联质量事件的记录在列表及展开区提供明确的“进入质量事件”入口；未通报、普通反馈和待补资料不会提前提供事件入口。
- 正式通报的演示操作只生成事件及入口，保留在反馈层；仍需点击入口进入事件页面。
- 质量事件是独立全宽详情页，隐藏反馈列表。返回全部反馈后恢复搜索、范围、筛选、页码、展开记录、来源子页签和滚动位置；浏览器后退、前进及事件页刷新也保留对应上下文。
- 直接访问不存在质量事件的反馈地址时，回到来源反馈层。

流程条位于质量事件详情的公共区域，在事件的所有页签中持续保留。点击阶段或页签只切换流程条下方的内容，不卸载记录标题、页签或流程导航。“业务进度”与“正在查看”分别标记，浏览其他阶段不会推进业务状态。任务分配与员工承办共用任务结果区，但各自保留查看标记。

进入质量事件后，详情有六个入口：

1. **处理总览**：阶段、当前处理人、下一步、任务完成情况和最新动态。
2. **OA 原始资料**：原始附件、表单、审批进度和来源版本；保留上一版附件预览、下载等交互。
3. **我的研判**：查看马荣鑫已保存的结论。未通报样例的处理方式、结论、保存草稿和确认提交操作在反馈层完成；只改变本次页面会话，刷新恢复演示。保存草稿不创建事件。
4. **佟成初析**：初析进度、方向、依据、结论、信息缺口、建议部门和期限；可以切换 V1/V2，历史只读。
5. **分配与承办**：正式任务的主管、承办人、要求、验收标准、期限、承接时间、自报进度、提交完成、证据和主管验收结果。按任务展开及筛选状态。
6. **验收与动态**：任务证据汇总、逐项主管验收、佟成终验、关闭结论及按环节筛选的公开处理记录。

后续处理在马荣鑫视角只读。不提供代替佟成写初析、直接改派员工、修改任务期限或代替主管验收的操作。未开始的环节明确展示空态，原型不虚构待初析、待分配样例中的结果。

- 顶部“原型说明与演示情境”可定位待初析、待分配、待终验、已关闭和待研判样例的来源反馈；已通报样例仍需点击“进入质量事件”查看后续流程。

- 在事件页点击 **返回全部反馈**，检查搜索条件、来源子页签和列表位置是否保留。

## 数据表达约束

- 员工提交即接入，不等待 OA 审批通过；接入与正式通报区分。
- OA 审批与质量进度独立展示；来源版本与初析版本分别记录。
- 来源事实、马荣鑫研判、佟成初析分开显示。
- 原始 OA 附件与后续任务证据分开；证据按任务归属，历史版本和退回意见保留。
- 员工自报进度、提交完成、主管验收通过和质量终验关闭分开，未用任务自报百分比冒充整体完成率。
- 并行任务不以箭头制造依赖；正式任务的人员、状态及期限在未来实现中仍由原任务系统提供。
- 当前原型展示范围由本次需求定义，不代表真实系统权限已迁移。
