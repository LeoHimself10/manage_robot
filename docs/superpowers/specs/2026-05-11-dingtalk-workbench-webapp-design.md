# 钉钉工作台网页应用设计（v1）

**文档日期**：2026-05-11  
**适用范围**：任务分配与追踪工作台 Web 应用（钉钉内访问）  
**设计状态**：已评审通过（Brainstorming 阶段）

## 1. 目标与范围

本设计用于定义钉钉工作台网页应用 v1，服务两类核心用户：

- 主管：查看并追踪自己分配的全部任务，查看每个子任务进度，发起新任务或编辑进行中任务。
- 员工：查看本人任务并提交自己子任务的进度与说明。

v1 功能目标：

1. 提供角色分离的工作台主页（主管页、员工页）。
2. 提供独立“任务对话中心”页面，支持“开启新任务”与“编辑进行中任务”。
3. 提供“进行中任务页”，按会话状态聚合当前处理中任务。
4. 对齐现有细版状态机，支持任务级/子任务级追踪。

非目标（v1 不做）：

- 不实现员工修改负责人。
- 不实现员工查看他人任务。
- 不引入新的人事权限系统（沿用钉钉用户信息识别 + 后端角色判定）。
- 不扩展到 OA 同步、验收闭环新增流程、看板/甘特等增强能力。

## 2. 入口与信息架构

### 2.1 统一入口

- 用户从钉钉网页应用进入。
- 后端基于钉钉用户信息识别身份与角色（主管/员工）。
- 依据角色重定向到对应首页。

### 2.2 页面结构

v1 固定为四页架构：

1. **主管首页（分配与追踪中心）**
2. **员工首页（我的任务）**
3. **任务对话中心（独立页）**
4. **进行中任务页（会话驱动）**

### 2.3 页面关系

- 主管首页与员工首页是日常入口。
- 对话相关操作统一跳转到“任务对话中心”。
- “进行中任务页”作为处理中队列，承接“继续处理会话”与“回到追踪确认”。

## 3. 关键页面设计

### 3.1 主管首页

核心目的：主管快速查看“自己分配出去的全部任务”并下钻子任务进度。

模块：

- 筛选区：默认“全部任务 + 筛选”（时间、状态机节点、负责人、来源、关键词）。
- 任务主表：任务行可展开子任务，显示状态、责任人、最近更新时间、风险标识。
- 详情抽屉：任务规划详情、分配历史、最近会话摘要、审计事件。
- 操作入口：查看对话、进入进行中任务页、发起重规划。

### 3.2 员工首页

核心目的：员工聚焦“我的任务”并更新本人子任务进度。

模块：

- 我的任务列表：仅显示本人相关任务/子任务。
- 子任务详情：目标、交付物、完成标准、时间节点、反馈频率。
- 进度提交区：更新本人子任务状态与说明（不可改负责人）。
- 异常反馈入口：阻塞、需协助、信息不足。

### 3.3 任务对话中心（独立页）

核心目的：把“任务追踪”和“任务对话”分离，减少主页面认知负担。

模式：

- **开启新任务**：从空白会话发起新规划与分配建议。
- **编辑进行中任务**：绑定既有任务上下文继续修改，不新建平行任务。

交互规则：

- 模型建议支持“应用为变更”或“仅记录备注”。
- 每次“应用为变更”都生成版本快照并写审计事件。

### 3.4 进行中任务页（会话驱动）

核心目的：聚合当前处理中的会话，形成“操作队列”。

分组维度：

- 待模型回复
- 待主管确认
- 待员工补充
- 已生成待应用

会话卡片包含：任务名称、会话阶段、最近摘要、下一步动作。  
支持快捷操作：继续对话、应用变更、回退上个版本、标记会话完成。

## 4. 状态机映射

前端显示沿用现有细版状态机，并映射到可理解的操作阶段：

- 草案阶段：`DRAFT_READY`
- 分配阶段：`ASSIGNMENT_RECOMMENDING`、`AWAITING_DISPATCH_CONFIRM`
- 派发后阶段：`DISPATCHED`
- 执行协同阶段：`NEGOTIATING`、`IN_EXECUTION`
- 验收收口阶段：`IN_ACCEPTANCE`、`DONE`

“进行中任务页”仅收录未结束会话，不展示 `DONE`。

## 5. 权限模型

### 5.1 主管权限

- 可查看：自己发起/分配的全部任务及全部子任务进度。
- 可操作：分配、重规划、发起新任务对话、编辑进行中任务。

### 5.2 员工权限

- 可查看：本人相关任务/子任务。
- 可操作：更新本人子任务状态和说明，提交阻塞或修改建议。
- 禁止：改负责人、改他人子任务、直接派发。

### 5.3 通用规则

- 所有写操作必须落审计事件。
- 对话驱动变更必须落版本快照。

### 5.4 主管名单（配置 B，预留）

- **与任务发起人白名单独立**：不使用 `TASK_INITIATOR_USER_IDS` 判定主管。
- 环境变量：**`WORKBENCH_MANAGER_USER_IDS`**（逗号分隔钉钉 `userId`）；可选 **`WORKBENCH_MANAGER_IDS_FILE`**（JSON 数组文件，语义对齐 `TASK_INITIATOR_IDS_FILE`）。
- 后端 helper：**`isWorkbenchManager(userId)`**（`src/security/workbench-manager-whitelist.ts`）。未配置或为空时人均视为 **非主管**（便于上线前占位，名单就绪后再放开主管路由）。

## 6. 数据与接口契约（v1 最小集）

v1 先提供以下 API（满足闭环）：

1. `GET /api/me`：返回当前用户与角色。
2. `GET /api/tasks`：任务列表（主管可全量筛选；员工仅本人）。
3. `GET /api/tasks/:taskId`：任务详情、子任务进度、最近事件。
4. `PATCH /api/subtasks/:subTaskId/progress`：员工更新本人子任务进度。
5. `POST /api/conversations/new-task`：开启新任务会话。
6. `POST /api/conversations/:id/messages`：会话发言（含编辑进行中任务）。
7. `POST /api/conversations/:id/apply`：应用模型建议为任务变更并生成新版本。
8. `GET /api/in-progress-sessions`：进行中任务页会话列表（按阶段分组）。

## 7. 数据流与一致性

1. 用户在对话中心发起或继续会话。
2. 模型返回建议，前端展示“应用/仅备注”选项。
3. 用户选择“应用”为任务变更。
4. 后端写入：
   - 新任务版本快照
   - 会话事件
   - 任务/子任务状态变化
5. 主管首页、员工首页、进行中任务页在下一次查询中反映最新状态。

并发策略：

- 以后端版本号作为并发控制依据。
- 冲突时返回可读错误并提示用户刷新重试。

## 8. 异常与恢复

- 模型超时：会话状态标记“待重试”，支持继续会话。
- 应用变更失败：会话记录保留，不生成任务新版本，前端提示重试。
- 权限失败（403）：前端明确提示“无权限操作”。
- 并发冲突（409）：前端提示“内容已变更，请刷新后重试”。

## 9. 测试与验收

### 9.1 测试重点

- 角色权限测试：主管/员工边界。
- 状态机映射测试：各阶段在四个页面可见性与可操作性。
- 会话闭环测试：新任务 -> 应用变更 -> 主管追踪页可见。
- 子任务进度测试：员工更新后主管可见最新进度。
- 异常恢复测试：超时、权限、并发冲突。

### 9.2 v1 验收标准

- 主管可查看自己历史分配的全部任务，并查看每个子任务进度。
- 员工可仅在本人任务范围内更新子任务进度与说明。
- 对话能力与主页分离，且支持“新任务/编辑进行中任务”双入口。
- 进行中任务页可稳定呈现未结束会话队列，并支持继续处理。
