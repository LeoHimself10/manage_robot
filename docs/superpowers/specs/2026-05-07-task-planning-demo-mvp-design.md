# 任务规划机器人 Demo MVP 设计

**文档日期**：2026-05-07  
**修订人**：姚凯珩  

## 1. 背景

质量侧对接后，当前产品目标从“完整任务闭环”收敛为先做一个可演示、可评估的任务拆解 Demo。Demo 重点验证 Agent 能否根据质量/研发任务背景完成输入质检、分类、WBS 拆解、任务包生成和派发门禁校验。质量后续会提供真实业务场景、分类口径和具体实例，用于优化 Agent 的分类与拆解效果。

本设计只覆盖 Demo/MVP，不包含 OA 自动流转、承接三态、电子签名、执行中延期/换人、节点反馈与验收闭环。这些能力作为后续版本演进。

## 2. 目标与非目标

### 2.1 目标

- 主管输入质量或研发任务背景后，Agent 先检查信息是否足够，不足则追问。
- Agent 对任务进行场景分类，并基于分类选择任务拆解模板。
- Agent 生成 WBS 草案和结构化任务包。
- Agent 对任务包执行派发门禁校验，确保交付物、完成标准、时间节点、反馈频率齐全。
- Agent 输出可复制到钉钉或文档中的 Markdown/表格结果。
- 对质量相关任务，Agent 输出是否建议开启 CAPA 的建议字段、理由和免责声明。

### 2.2 非目标

- 不自动创建钉钉 OA 审批流程。
- 不处理员工认领、拒绝、延期、无法完成或换人审批。
- 不接入电子签名。
- 不做执行中的节点反馈、验收和复盘。
- 不把 CAPA 建议作为正式质量体系判断，最终仍以质量授权人员和 QMS 流程为准。
- 不依赖 HR 简历自动分配任务；若展示人员建议，必须标注能力信息可能过时。

## 3. 推荐方案

采用“流水线 + 轻状态”的设计，而不是一次性让模型输出所有内容。

流程为：

```text
输入质检 -> 场景分类 -> CAPA 建议 -> 模板装配 -> WBS 生成 -> 派发门禁 -> Markdown 输出
```

这种方案比单次生成更适合 Demo 后续迭代，因为质量提供真实案例后，可以分别评估分类、CAPA 建议、任务模板和门禁结果，而不是只评估最终文本是否“看起来合理”。

## 4. 核心流程

### 4.1 输入质检

Agent 首先判断主管输入是否足以拆解任务。质量类任务重点检查：

- 问题来源。
- 产品、批次、版本或使用场景。
- 问题现象。
- 影响范围。
- 当前是否已有证据。
- 是否存在客户、生产、出货、安全或法规影响。
- 期望完成时间或关键时间约束。

信息不足时，Agent 只输出追问清单，不生成 WBS。

### 4.2 场景分类

Demo 先支持小集合分类：

- 质量：生产/过程异常、检验/测试异常、客诉/售后、供应商问题、设计相关质量任务、其他/不确定。
- 研发：需求/设计输入落地、方案开发与论证、验证与确认任务、设计变更行动项、其他/不确定。

分类输出需包含：

- 分类结果。
- 置信度或判断依据。
- 若不确定，列出需要补充的信息。

### 4.3 CAPA 建议

CAPA 字段为纯建议，不具备正式质量体系效力。输出结构：

```text
capa_advisory: NOT_REQUIRED | RECOMMENDED | UNCERTAIN | INSUFFICIENT_INFO
capa_rationale: 建议理由列表
capa_disclaimer: “该建议仅用于任务拆解与质量沟通参考，最终是否开启 CAPA 以质量授权人员和公司 QMS 流程判定为准。”
capa_prompting_questions: 当信息不足或不确定时，列出需要质量补充的问题
```

Demo 阶段不固化 CAPA 规则，只基于输入信息给建议。待质量提供触发规则后，可升级为规则驱动或规则 + Agent 的混合判断。

### 4.4 模板装配与 WBS

Agent 根据分类选择模板骨架，再填充任务包。质量类默认可参考：

- 问题事实确认。
- 临时遏制或影响控制。
- 根因分析。
- 纠正措施建议。
- 效果验证或关闭准备。

上述任务不是所有场景都强制出现，Agent 需要说明为什么保留或不保留。

### 4.5 派发门禁

Demo 阶段保留派发门禁，但不真正派发。门禁校验每个子任务是否包含：

- 交付物。
- 完成标准。
- 时间节点。
- 反馈频率。

若缺失，则输出“门禁未通过”和缺失项清单，不输出“可派发最终稿”。

## 5. 输出形态

Demo 输出以 Markdown 为主，方便复制到钉钉、文档或评审材料中。建议包含：

1. 任务理解摘要。
2. 场景分类与依据。
3. CAPA 建议、理由和免责声明。
4. WBS 总览。
5. 子任务包表格。
6. 派发门禁结果。
7. 仍需主管/质量确认的问题。

## 6. 后续演进

Demo 验证拆解效果后，再考虑以下能力：

- 员工执行中申请延期、无法完成或变更任务，提交主管审核并可委托新承接人。
- 钉钉 OA 审批自动创建与状态同步。
- 承接/拒绝时接入电子签名，并同步到 OA 留存。
- 外部 Agent Web 链接，用于复杂表格编辑与跨钉钉/飞书复用。
- HR 能力清单增强：从简历升级为结构化、带更新时间与任务表现反馈的能力画像。

## 7. 测试与评估

Demo 评估以真实样本为主。质量后续提供案例后，至少形成 10 条黄金样本，用于评估：

- 分类是否合理。
- CAPA 建议是否符合质量人员预期。
- WBS 是否覆盖关键处理步骤。
- 任务包交付物与完成标准是否清晰。
- 门禁是否能发现缺失字段。

## 8. 风险与缓解

- HR 简历可能过时：Demo 不把 HR 推荐作为核心能力；后续若展示推荐，必须显示来源与更新时间。
- CAPA 建议被误解为正式结论：所有输出必须包含免责声明，并在 PRD 中标注最终以 QMS 和授权人判定为准。
- 模型分类不稳定：用真实样本建立回归集，逐步优化分类模板和提示词。
- Demo 范围膨胀：OA、电子签、承接闭环和外部 Web Agent 都不进入当前 MVP。

## 9. 本地 Demo 运行方式

实现完成后，可用以下命令运行：

```bash
npm install
npm test
npm run typecheck
npm run demo
```

`npm run demo` 会输出一份 Markdown 任务拆解草案，包含输入理解、分类、CAPA 建议、WBS 任务包、派发门禁和仍需确认的问题。
