# 杨贺新多角色管理员权限设计

日期：2026-07-14  
状态：已确认，待实施

## 一、目标

在当前质量追踪开发环境中，为钉钉成员“杨贺新”配置管理员身份，并允许其访问管理员、主管、员工、售后主管和质量专员所需页面。杨贺新同时拥有质量异常通报与质量专员终验能力，但不得因管理员身份越权读取第三方私密质量评论。

本次只修改当前开发分支及本地开发配置，完成自动化和本地页面验证，不修改现网配置，不部署现网。

## 二、身份识别

- 权限判断只使用钉钉通讯录中唯一匹配“杨贺新”的真实 `userId`。
- 不使用显示姓名进行运行时权限判断，避免重名或改名导致授权错误。
- 真实 `userId` 只写入本地、非版本控制的开发配置，不写入公开文档、示例配置、测试代码或提交历史。
- 解析时若出现零个或多个同名联系人，停止配置并报告错误，不猜测账号。

## 三、授权方案

复用现有多角色机制，不新增“超级管理员”角色，也不改变其他管理员的权限。

将同一个 `userId` 合并加入以下配置，保留原有成员：

- `WORKBENCH_ADMIN_USER_IDS`：管理员页面与管理员接口。
- 主管名单（`WORKBENCH_MANAGER_USER_IDS` 或开发环境对应动态主管文件）：主管页面、任务分配和主管日常操作。
- `QUALITY_AFTERSALES_MANAGER_USER_IDS`：新建、编辑并通报质量异常。
- `QUALITY_SPECIALIST_USER_IDS`：查看全部已通报质量事件公开链路，分配原主责，执行终验、指定节点退回、关闭与重开。

管理员与主管双角色沿用现有登录行为：默认进入主管日常工作台，侧栏允许切换管理员、主管和员工视图。质量相关入口按独立质量角色显示。

## 四、页面与操作边界

杨贺新应能访问：

- 管理员运营看板、权限中心及其他已启用管理员页面。
- 主管历史任务、项目、周度看板、交付绩效、智能规划助手和任务快录入库等已启用页面。
- 员工任务页面。
- 质量追踪页面，并同时拥有售后主管与质量专员操作。
- 质量意见页面。

私密质量评论继续执行既有双方关系校验：

- 仅评论人和该对话对应的质量专员可查看和回复。
- 管理员身份不构成旁路权限。
- 杨贺新只能看到自己作为质量专员或评论人实际参与的私密对话。
- 不修改私密评论正文的存储、通知与审计隔离规则。

## 五、实现边界

- 优先完成本地开发配置，不改动生产 `/etc/manage-robot*.env`、生产数据卷或运行容器。
- 若现有多角色能力与质量角色组合已经满足要求，不新增业务角色或放宽服务端授权。
- 仅在测试发现组合入口或切换能力缺失时，进行最小代码修正并补充回归测试。
- 本地配置更新必须按集合合并，禁止覆盖或删除已有管理员、主管、售后主管和质量专员。

## 六、验证方案

### 自动化验证

- 同一 `userId` 同时解析为管理员主角色和主管附加能力。
- 管理员、主管、员工页面访问均成功。
- 质量追踪页面同时显示通报与质量专员操作入口。
- 质量专员公开全链查询成功。
- 私密评论仍拒绝未参与对话的管理员访问。
- 其他普通管理员、主管、员工及质量角色权限不发生变化。

### 本地页面验证

- 使用杨贺新的开发身份登录。
- 核对侧栏页面入口和管理员、主管、员工视图切换。
- 核对质量追踪新建通报、分配原主责、终验、退回、关闭和重开控件。
- 核对质量意见页面只能展示本人参与的私密对话。
- 检查页面控制台无运行错误。

## 七、完成标准

- 杨贺新在开发环境中可访问全部约定页面并执行质量专员操作。
- 私密评论权限没有管理员旁路。
- 真实 `userId` 未进入 Git 历史。
- 自动化测试和本地页面验证通过。
- 未部署或修改现网。
