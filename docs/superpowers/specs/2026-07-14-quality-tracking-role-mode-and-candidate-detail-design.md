# 质量追踪：角色工作模式与异常候选详情

## 目标

让同时具有售后主管、质量专员身份的用户明确切换工作模式；让售后主管在通报前能够理解异常候选、查看关联反馈并编辑预填草稿。

## 范围

### 角色工作模式

`/workbench/quality` 保持为唯一入口。后端向页面传递售后主管和质量专员两项独立能力。

- 仅售后主管：固定显示售后主管模式。
- 仅质量专员：固定显示质量专员模式。
- 同时具备两者：页面顶部显示“售后主管”“质量专员”切换；默认售后主管模式，与既有操作习惯一致。

售后主管模式保留异常候选、反馈来源、草稿和“我通报的事件”。质量专员模式显示按状态分组的事件处理视图，并保留既有分派、退回、关闭等操作权限。

### 异常候选

候选卡片显示候选结论之外的可判断信息：触发规则、型号/类别/关键词等命中事实，以及关联反馈摘要。

卡片提供“查看详情并编辑通报”操作。用户先在弹窗中查看候选及关联反馈；确认后以候选的 `sourceKeys` 创建或打开草稿，进入既有草稿编辑表单。保留“忽略”操作。

候选本身仍是系统建议，不提供对候选记录的直接编辑；用户编辑的是将要提交的质量事件草稿。

## 数据流

候选列表继续从既有 candidates API 获取。其 `explanation.triggers[].facts` 与 `sourceKeys` 已由后端提供，前端直接渲染，不新增表或接口。

模式切换只影响页面上的标签、列表筛选与操作入口；服务端仍按现有角色能力进行授权，不能因切换而提升权限。

## 错误处理

创建草稿若发现来源已被通报，沿用现有冲突提示；候选详情加载失败或草稿创建失败，沿用页面既有错误提示。无候选事实或无关联反馈时显示明确空状态。

## 验证

- 页面渲染测试覆盖三种能力组合及双角色模式切换控件。
- 候选渲染测试覆盖事实、关联反馈和“查看详情并编辑通报”入口。
- 运行目标测试、TypeScript 类型检查和完整测试套件。
