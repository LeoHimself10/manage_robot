# 管理员全公司任务筛选修复设计

## 问题

管理员“全公司正式任务”页面会把业务编号和发起部门传给后端，但 SQLite 查询使用完全相等匹配。管理员输入部分业务编号或部门简称时，即使存在对应任务也会返回空结果，因此筛选看起来不可用。

## 设计

- 保持页面请求参数和 API 接口不变。
- 将 `listAdminTasks` 中的业务编号条件从完全相等改为不区分大小写的包含匹配。
- 将发起部门条件从完全相等改为不区分大小写的包含匹配。
- 状态继续使用精确匹配；负责人和标题关键词维持现有包含匹配逻辑。
- 空筛选值仍不限制结果，多个非空条件继续使用 AND 组合。

该方案只修正数据查询语义，不改页面布局、权限、返回结构或任务状态口径。

## 验证

先增加存储层回归测试，发布两条可区分的任务并验证：

1. 部分业务编号只命中对应任务。
2. 部门简称只命中对应部门任务。
3. 多条件组合仍取交集。
4. 空筛选和现有精确状态筛选保持有效。

测试必须先在现有实现上因部分匹配失败而变红，再修改 SQL 使其通过；随后运行相关测试、类型检查和内联页面检查。
