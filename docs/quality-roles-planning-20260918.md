# 质量岗位与成果任务规划 r14

状态：2026-09-18 已部署至独立钉钉质量测试入口。版本 `quality-test-roles-planning-20260918-r14`，源码提交 `2a9ce4f`，分支 `codex/quality-roles-planning-20260918`。

## 改动范围

- 业务页面和操作记录的岗位标签改为客服主管、质量主管；管理员配置可以识别具体人员，原始来源快照与真实操作人审计不改写。
- 管理员独占岗位配置接口，目录搜索、明确交接确认、乐观版本校验；真实/测试岗位各自保存。业务岗位能力不自动授予原任务系统主管权限。
- 每次请求重新核验岗位，旧登录会话也即时失去原岗位权限。客服来源和草稿沿历史岗位链继承，质量主管按质量能力接续全部事件。已发放部门任务不随岗位换人改派。
- 质量初析成果不是任务清单。新移交只含待规划占位；主管 AI 规划或手工编排后明确成果对应。一成果一最终任务，可有多个支撑任务；一个任务可最终交付多个成果。
- 确认过的结构摘要用于选人/发布校验。结构、交付物、标准和依赖修改须重新确认；人员与日期仍走原系统。确认会清理已删除任务的人员配置，自动带入最终成果/验收要求，成果改挂会移除原任务的自动带入项。

## API 和持久化

- `GET/POST /api/quality-posts?scope=real|test`：仅管理员，修改包含 post、userId、expectedVersion、confirmTransfer。
- `GET /api/quality-posts/people`：管理员查询独立通讯录快照，不开放模拟执行人。
- `POST /api/workbench/conversation/draft/quality-plan`：接收该初析的主管，须提供 planId、threadId、expectedHash、tasks、mappings；校验未发放的权威移交记录。
- 新增 quality_posts、quality_post_audit、quality_post_operations、quality_post_directory、quality_execution_plans；只追加岗位配置、审计和方案版本。不迁移普通正式任务状态，不覆盖旧分析、证据和记录。
- scope 由服务端身份上下文确定，不能由业务请求体切换。管理员测试操作另记真实登录账号与代理岗位账号。
