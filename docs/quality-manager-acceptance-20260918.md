# 主管移交承接与完成文案 r16

状态：隔离验证通过，待发布。

## 问题及改动

原初析确认直接生成 PENDING_PLANNING 移交和侧会话，主管阶段回退为 DELEGATE，缺少显式承接。因此用户截图中两条未发放事项直接进入“待分派员工”。

新增 quality_handoff_acceptances，按 handoff_id 唯一记录接收主管、真实操作人和承接时间。只允许最新移交的指定主管承接；重复请求幂等，承接与 QUALITY_HANDOFF_ACCEPTED 审计同一事务。不迁移或重写已有手工分析、草案、正式任务及员工状态。

主管列表/详情以是否承接区分 ACCEPT 与 DELEGATE。未承接显示“确认承接”，承接成功后才提供原任务分配链接。旧规划深链转回主管工作台；草案结构、人员、标准、表格、花名册和 AI 对话修改均检查承接；发放预检与发放从 planId 查询权威移交，即使草案丢失质量标签也不能绕过。普通任务保持原流程，已发放的历史事项无需补承接。

质量主管总览时段统计卡片“终验关闭”改为“流程完成”，筛选标签同步；统计含义仍为该时段完成终验关闭的事件，未改变数据口径。

## API 与验证

新增 POST /api/workbench/quality/handoffs/accept，body 为 eventId、handoffId；经理会话及指定接收人双重验证，旧移交编号拒绝。

TypeScript、内联页面检查通过；相关质量/权限/投影回归 150 项通过。承接测试覆盖未承接发布拦截、正常承接、重复承接、错误接收人、审计和原草稿保留。原有两项 quality-test-ai-service 失败已在 r13 复现，与本次无关。

隔离副本真实 HTTP 核验截图中的两条事项均先进入待承接；承接前旧规划深链重定向，AI/结构/人员/标准接口拒绝；员工及过期移交编号拒绝。承接后进入待分派，原草稿完全相同，没有提前创建正式员工任务，重复承接只产生一条审计。

Playwright 经隔离 SSH 隧道实际点击确认承接：1366×768 和 1920×1080 无横向溢出，未承接不显示分配链接；成功后出现“进入任务分配”。使用隔离测试签名，未伪造真实登录或代用户承接线上事项。

发布仅替换独立质量测试容器，保留 r15 回滚镜像，发布前备份全数据与 SQLite 快照，核对历史表记录不变。
