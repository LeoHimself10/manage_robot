# 质量追踪 HTML 交互规格

## 1. 页面与实现形态

当前页面不是 React SPA。服务端 TypeScript 生成 HTML、CSS 和原生浏览器 JavaScript，浏览器使用 `fetch` 调用同一 Node.js 服务的 JSON API。

- 反馈研判真实页：`src/web/quality-review-page.ts`、`src/web/quality-review-styles.ts`。
- 质量追踪真实页：`src/web/quality-tracking-page.ts`、`src/web/quality-tracking-styles.ts`。
- 私密意见真实页：`src/web/quality-opinions-page.ts`。
- 综合交互原型：`docs/mockups/quality-tracking-interface-prototype.html`。
- 统一 HTTP 和页面权限入口：`src/web/quality-http.ts`。

原型用于表达目标信息架构和交互方向，真实页用于确认当前可运行行为。二者冲突时不得直接把原型描述成已实现。

## 2. 反馈研判工作台

### 页面信息

- 路由：`/workbench/quality/review`。
- 角色：仅 `aftersales_manager`。
- 页面目的：先看风险和集中趋势，再由售后主管作正式人工判断。
- API 数据：真实读取 SQLite，不是写死的静态列表。

### 页面结构

1. 顶部命令区：页面说明、同步状态、立即同步、打开钉钉原表。
2. 指标区：待研判、高风险、集中问题、资料已更新、待补资料。
3. 视图切换：研判队列、集中问题。
4. 范围切换：待判断、待补资料、已完成。
5. 筛选条：关键词、风险、设备型号、问题分类。
6. 三栏主体：反馈队列、来源事实与证据、研判辅助。
7. 研判备注弹窗。
8. 质量异常草稿/提交弹窗。

### UI-QR-001 首次加载

触发：页面脚本初始化。

行为：

- 请求来源同步状态，显示最近成功时间或“尚无成功同步记录”。
- 默认范围为 `UNREVIEWED`，请求第 1 页、最多 200 条。
- 显示加载占位；成功后写入指标、筛选选项、队列和第一条详情。
- 没有数据时显示“当前范围没有待处理反馈”。
- 请求失败时，队列显示错误、详情显示加载失败、辅助区显示暂不可用。

接口：

- `GET /api/workbench/quality/source`
- `GET /api/workbench/quality/review-queue?scope=UNREVIEWED&...`

### UI-QR-002 切换研判范围

触发：点击“待判断”“待补资料”或“已完成”。

行为：

- 更新激活按钮并清空当前选择。
- 若当前在集中问题视图，先返回研判队列视图。
- 重新请求队列。
- `COMPLETED` 同时包含 `ORDINARY` 和 `REPORTED`。

### UI-QR-003 搜索与筛选

触发：输入关键词、选择风险/型号/分类并点击“筛选”。

行为：清空当前选择并重新加载。关键词匹配反馈单号、反馈人、型号、序列号、批次、问题描述和分类；风险支持全部、高风险、重复问题和无风险标签。

### UI-QR-004 选择反馈

触发：点击左侧队列卡片。

行为：

- 当前卡片高亮，不额外请求详情接口。
- 中栏展示反馈时间、反馈人、型号、序列号、批次、分类、问题描述、原表处理信息、异常依据、关联反馈、研判备注和回写状态。
- 卡片和详情按数据添加高风险、重复问题、资料已更新、普通反馈、待补资料、已进入后续流程标签。
- 右栏同步渲染规则辅助或可选 `aiAdvice`。

### UI-QR-005 规则辅助区域

当前实现：

- 若后端项目包含 `item.aiAdvice`，页面可展示建议结论、原因、缺失字段、建议草稿和数值置信度。
- 当前 `quality-review-query.ts` 不返回 `aiAdvice`，因此真实运行时进入规则辅助分支。
- 规则辅助根据高风险、重复/历史相似信号生成提示，并检查反馈时间、设备序列号、导管批次、影响说明和确认情况是否缺失。
- 始终显示“AI仅提供建议，正式研判结果以售后主管确认为准”。

限制：本基线不设计未来 AI 服务。不得把“AI研判助手”标题理解为已接入大模型。

### UI-QR-006 查看集中问题

触发：点击“集中问题”。

行为：

- 若当前范围不是 `UNREVIEWED`，自动切回待判断并重新加载。
- 浏览器基于当前最多 200 条数据和 `relatedFeedback` 建立关联分组。
- 仅保留至少 2 条或已命中重复规则的组，按高风险和数量排序，截取 Top 5。
- 展示主题、涉及型号、最多 3 条样本、关联数量和在当前查询结果中的占比。
- 点击“查看代表反馈”返回队列并选中代表反馈。

限制：这不是严格的近三个月全量语义聚类；数量和占比只针对当前客户端加载范围。

### UI-QR-007 标记普通反馈

触发：点击“普通反馈”。

前置：来源未处于 `REPORTED`。

行为：打开备注弹窗，备注最多 2000 字；确认后发送 `decision=ORDINARY`、当前 `expectedVersion` 和新 `requestId`。成功关闭弹窗、清空选择并重新加载；失败在弹窗内显示错误。

接口：`POST /api/workbench/quality/source/{sourceKey}/review`。

### UI-QR-008 标记待补资料

触发和反馈方式同普通反馈，发送 `decision=NEEDS_INFO`。来源内容后续变化时卡片出现“资料已更新”。

### UI-QR-009 打开通报表单

触发：点击“通报质量异常”。

行为：

- 重置表单。
- 用来源分类/型号/反馈单号生成默认标题。
- 预填问题描述、反馈时间、反馈人、型号、序列号、批次、分类和影响。
- 紧急度默认 `MEDIUM`。
- 用户可修改事件标题、当前情况、发生时间、反馈人、型号、序列号、批次、分类、紧急度、影响和补充说明。

若未来后端提供 `suggestedDraft`，页面已有“采纳建议并预填通报”入口；当前没有真实建议草稿来源。

### UI-QR-010 保存质量事件草稿

触发：通报弹窗点击“保存草稿”。

行为：调用草稿创建接口并关联当前来源，成功后保持弹窗打开并提示可到“我通报的事件”继续编辑。保存草稿不会把来源标记为 `REPORTED`。

接口：`POST /api/workbench/quality/events/drafts`。

### UI-QR-011 提交质量异常

触发：提交通报表单。

行为：先创建草稿，再以返回的事件版本调用提交接口。两步成功后关闭弹窗、清空选择、重新加载队列；事件服务在提交事务中把关联来源标记为 `REPORTED`。

接口：

- `POST /api/workbench/quality/events/drafts`
- `POST /api/workbench/quality/events/{eventId}/submit`

### UI-QR-012 查看已通报事件

当来源状态为 `REPORTED` 时，不再显示三种研判按钮，改为“查看质量事件”，新窗口打开 `/workbench/quality?eventId={eventId}`。

### UI-QR-013 人工同步来源

触发：点击“立即同步”。

行为：同步状态变为“正在同步来源…”，成功后显示“来源同步完成”并保留当前选择重新加载；失败直接显示错误信息。按钮当前没有显式禁用，但服务端用共享 Promise 避免并发人工同步重复执行。

接口：`POST /api/workbench/quality/source/sync`。

### UI-QR-014 回写失败重试

当最新回写状态为 `DEAD` 时，详情显示“重新回写”。点击后把失败任务重新入队并刷新详情。没有终态失败任务时服务端返回错误。

接口：`POST /api/workbench/quality/source/{sourceKey}/writeback/retry`。

### 可访问性和响应式

- 动态队列、详情、辅助区和集中问题区域使用 `aria-live`。
- 对话框有标题关联和关闭按钮；操作失败在对话框反馈区域展示。
- 窄屏时三栏布局收敛为单列，操作区和筛选区允许换行；具体断点在 `quality-review-styles.ts`。
- 页面通过服务端权限拒绝非售后主管，不能只依赖隐藏按钮。

## 3. 质量追踪主工作台

### 页面信息

- 路由：`/workbench/quality`。
- 角色：售后主管或质量专员。
- 双角色用户可在“售后主管/质量专员”视角间切换；单角色用户只显示自己的视角。

### 当前导航逻辑

售后主管视角包含：

- 打开研判工作台。
- 新建质量异常。
- 来源反馈、规则候选、我通报的事件等当前标签。

质量专员视角包含：

- 全部质量事件。
- 状态提示：待分配、待承接、处理中、待原主责确认、待终验、已关闭。
- 事件详情允许的操作由服务端 `allowedActions` 决定。

### UI-QT-001 切换角色视角

点击视角按钮后：更新根节点 `data-quality-mode`、隐藏另一个视角的元素、重置到该视角的首个标签、重新加载当前数据。视角切换只改变当前用户已有权限下的呈现，不授予新权限。

### UI-QT-002 浏览来源反馈

支持分页和搜索，列表显示来源状态、反馈信息和已通报事件。未通报来源可从快照创建事件草稿；已通报来源打开关联事件。

### UI-QT-003 浏览异常候选

候选列表展示触发规则和关联来源。可打开详情核对异常依据与关联反馈，再创建可编辑通报草稿；也可填写原因忽略候选。被忽略候选的来源内容变化后可由检测器重新打开。

### UI-QT-004 手工新建事件

售后主管点击“新建质量异常”打开无来源草稿表单。来源快照区显示“手动新建，无关联来源”。可保存草稿、上传单个不超过 20MB 的附件，再显式提交。

### UI-QT-005 编辑和提交草稿

新草稿使用 `POST /events/drafts`；已有草稿使用带 `expectedVersion` 的 `PATCH /events/{id}/draft`。提交表单时先保存草稿，再调用 `/submit`。版本冲突和字段校验错误显示在表单反馈区。

### UI-QT-006 查看事件详情

详情包括：原始通报、来源快照、相关事件、分配链路、证据与验收、通知记录和公开审计。页面只显示服务端允许的操作，通知错误对非质量专员脱敏。

### UI-QT-007 质量专员事件操作

真实页面当前通过通用业务操作交互处理：分配原主责、调整总期限、指定节点退回、关闭质量事件、重开质量事件、补充情况和更正信息。操作前使用提示框/选择框收集必要数据，成功后重新打开事件详情。

限制：这些交互目前功能可用但表现较粗糙，综合原型中的专门表单不等于已经接入真实页面。

### UI-QT-008 通知重新入队

质量专员看到状态为 `DEAD` 的通知时可点击“重新入队”；操作期间按钮禁用，完成后刷新事件详情。其他角色不显示敏感错误和重试入口。

## 4. 私密质量意见页

### 页面信息

- 路由：`/workbench/quality/opinions`。
- 质量意见人员看到可建立会话的事件和自己的会话。
- 质量专员看到与配置下级相关的会话。

### 交互边界

- 质量意见人员按事件和对应质量专员创建线程。
- 双方选择线程、查看按时间排序的历史消息并发送新消息。
- 事件关闭后不能继续发送。
- 服务端逐次验证线程双方身份，第三人和 admin 不能查询或发送。
- 消息通知不包含正文；正文不进入公开质量链路。

## 5. 综合 HTML 原型

文件：`docs/mockups/quality-tracking-interface-prototype.html`。

原型包含以下目标页面：

1. 反馈研判。
2. 质量事件总览。
3. 跨部门执行链路。
4. 质量终验与归档。
5. 质量意见实时会话。

原型支持售后主管/质量专员视角切换、事件状态筛选、反馈选择、Top 5 覆盖层、来源预览、事件侧栏、初步分析表单、阶段计划、技术与客户可读进展、预警规则、证据版本、终验检查和私密意见对话。

所有原型数据和“保存/导出/同步/打开工作台”等动作都是浏览器内模拟，不写 SQLite，也不调用真实 API。原型中的人员、事件编号、数量、百分比、日期、相似度和置信度均为演示内容。

## 6. 原型与真实页面对照

### 已在真实页面落地

- 售后主管专属研判入口。
- 来源同步状态和人工同步。
- 队列、范围、风险/型号/分类/关键词筛选。
- 来源事实、规则依据、关联反馈、缺失字段和回写状态。
- 普通、待补资料、保存草稿、通报质量异常。
- 来源回写 outbox 和失败重试。
- 质量事件列表、详情、来源快照、责任树、证据、通知和审计。
- 私密质量意见独立页面。

### 只在原型中完整表达

- 真正统一的近三个月 Top 5 统计口径和全量聚类。
- 质量专员派发前的结构化初步分析、证据核对和“分析完成”门禁。
- 阶段计划、计划进度与实际进度并列展示。
- 客户可读进展的独立编辑、下一次同步时间和历史。
- 完整预警面板和低于 80% 的业务提醒交互。
- 专门的终验检查单和关闭文案校验交互。

### 原型表达需要谨慎的部分

- 原型把“AI研判助手”画成已有能力，真实系统当前只是规则辅助和预留字段。
- 原型的“质量意见”演示参与人比当前源码权限口径更宽，真实权限以配置下级与对应质量专员双方为准。
- 原型中的执行链路是目标聚合视图，实际承接和执行仍在原任务工作台。

## 7. 页面修改验收清单

- 页面可见性与 API 权限一致，不能只隐藏按钮。
- 所有真实动作明确调用哪个 API；模拟动作必须标注原型。
- 加载、空数据、失败、无权限、版本冲突和重复提交均有反馈。
- 来源事实始终只读，业务表单另存。
- 草稿保存和正式提交语义分离。
- 规则辅助不能自动通报。
- 已通报来源只能查看事件，不能在研判页撤回。
- 响应式布局不遮挡关键操作，键盘可关闭对话框并恢复焦点。
- 修改交互后同步更新本文件、相关页面测试和 `last_verified_at`。
