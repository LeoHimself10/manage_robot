一套平台 · 两种用法

有人要「大项目」归类；有人只要拆解与追踪。项目做成可选层，不强迫所有人。

项目 = 可选标签，不是人人必填 底层仍是：大任务 → 子任务 → 承接/催办。项目只给需要的人加导航。
角色 A · 多专项主管

要「大项目」

  • 管多条业务线 / 专项
  • 列表、日报按项目看
  • 机器人建议归入哪项

工作台：项目侧栏 → 任务列表

角色 B · 拆解追踪为主

不要「项目」

  • 发需求 → 拆 WBS → 点将 → 追踪
  • 不关心项目档案
  • 任务标题 + 状态就够

工作台：保持现网扁平列表

同一套数据，叠一层可选的

大项目 Project 可空 · 仅角色 A 常显
大任务 Task 一次发放 · 0.1.2…
子任务 Subtask 承接 · 催办 · 进展

怎么做到「适合两边」

能力角色 A角色 B
创建 / 选项目有默认不出现
发放任务必选项目可配置强制不强制
历史任务列表按项目筛选扁平 + 关注状态（现网）
钉钉规划助手显示当前项目 chip无项目 chip
机器人归类建议项目 + 确认不问项目，直接拆
每日进展 / 催办可按项目汇总按主管 / 任务（现网）
🤖

机器人：先识别用户模式（或看是否开启「项目管理」）。A 类 → 列项目再建议；B 类 → 跳过项目，走 CLARIFY / DRAFT / 发放。
