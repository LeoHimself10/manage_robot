# 钉钉「任务规划与承接确认」机器人 — 场景流程图

**关联文档**：[PRD-钉钉任务规划与承接确认机器人.md](./PRD-钉钉任务规划与承接确认机器人.md)  
**用途**：开发实现边界、测试场景路径、质量/研发业务对接对齐  
**版本**：v1.1（与 PRD v1.1 对齐）

## 1. Demo / MVP 总览（任务拆解主链路）

```mermaid
flowchart LR
  A[发起] --> B[输入质检 / 追问缺失]
  B --> C[场景分类与模板]
  C --> D{质量任务?}
  D -->|是| E[CAPA 建议字段<br/>建议/理由/免责声明]
  D -->|否| F[跳过 CAPA 建议]
  E --> G[WBS 草案 + 任务包]
  F --> G
  G --> H[发起人审阅与修订]
  H --> I{派发门禁通过?}
  I -->|否| J[列出缺失项<br/>回到修订]
  J --> H
  I -->|是| K[输出可复制拆解稿<br/>Markdown/表格]
  K --> L[业务评审 Demo 效果]
```

## 2. 任务拆解生成（含输入质检、分类、CAPA 建议、门禁）

```mermaid
flowchart TD
  S[任务发起人输入背景/需求] --> Q{信息是否充足?}
  Q -->|否| R[优先追问缺失信息]
  R --> S
  Q -->|是| T{选择域}
  T --> TQ[质量域 + 子类型模板]
  T --> TR[研发域 + 子类型模板]
  TQ --> CAPA[CAPA 建议<br/>NOT_REQUIRED / RECOMMENDED / UNCERTAIN / INSUFFICIENT_INFO]
  CAPA --> W[生成 WBS：子任务 + 依赖]
  TR --> W
  W --> REV[发起人审阅与编辑任务包]
  REV --> G4{四必填齐全?<br/>交付物/完成标准/时间节点/反馈频率}
  G4 -->|缺项| BLOCK[门禁未通过<br/>输出缺失项]
  BLOCK --> REV
  G4 -->|齐全| OUT[输出可复制拆解稿<br/>Markdown/表格]
```

**对接说明**：MVP 只验证任务拆解效果，不进入正式派发、承接确认、OA 流程和电子签。质量 / 研发子类型与模板文案由业务确认（参见 PRD §3.2、§9）；研发模板强调「范围边界」。

## 3. 后续版本：强制承接确认（不进入当前 MVP）

```mermaid
flowchart TD
  DIS[收到派发卡片] --> CH{承接人选择}
  CH --> C1[确认承接]
  CH --> C2[需要修改]
  CH --> C3[无法承接]
  C1 --> OK[记录状态与时间戳]
  C2 --> MOD[填写：不清晰项/缺输入/建议调整]
  C3 --> REJ[填写：原因/冲突/能力/建议替代人]
  MOD --> AGG[发起人汇总修订计划]
  REJ --> AGG
  AGG --> REV2[更新任务包后再次派发或关闭支线]
  OK --> EXEC[进入执行与节点反馈]
  SILENCE{超时未操作?}
  DIS --> SILENCE
  SILENCE -->|首次超时| REM1[提醒承接人]
  SILENCE -->|再超时| ESC[升级提醒发起人]
```

**测试要点**：不允许「默认接受」；三态必选其一；提醒与升级策略可配置（FR-07）。

## 4. 后续版本：执行中节点反馈（不进入当前 MVP）

```mermaid
flowchart TD

  VF --> FEV
  PL --> FEV
  NODE -->|否| EXEC
  FEV --> EXEC
```

## 5. 后续版本：验收与可选复盘（不进入当前 MVP）

```mermaid
flowchart LR

  ACC -->|通过| DONE[任务完成留痕]
  ACC -->|不通过| RET[退回补充/改派]
```

## 7. 质量域 vs 研发域（首期场景入口差异）

```mermaid
flowchart LR
  subgraph 质量域示例
    Q1[生产/过程异常]
    Q2[检验/测试异常]
    Q3[客诉/售后]
    Q4[供应商问题]
    Q5[设计相关质量任务]
  end
  subgraph 研发域示例
    R1[需求/设计输入落地]
    R2[方案开发与论证]
    R3[验证与确认任务]
    R4[设计变更行动项]
  end
  Q1 & Q2 & Q3 & Q4 & Q5 --> WBS[统一任务包结构 + WBS]
  R1 & R2 & R3 & R4 --> WBS
  Q1 & Q2 & Q3 & Q4 & Q5 --> CAPA[CAPA 建议字段]
  CAPA --> WBS
  WBS --> GATE[同一派发门禁]
  GATE --> OUT[输出 Demo 拆解稿]
```

## 9. 待决策项对流程的影响（评审前标灰区域）

以下 PRD §12 决策会改变实现分支，建议在详设前锁定：

1. **质量首期子类型** → 影响 FR-01 模板清单与验收案例集。  
2. **真实样本集** → 影响分类、CAPA 建议和 WBS 拆解的回归评估。  
3. **CAPA 建议评估口径** → 影响 `RECOMMENDED` / `UNCERTAIN` 的验收标准。  
4. **研发需求/风险 ID** → 任务包「追溯信息」是否必填。  
5. **后续集成优先级** → 决定 OA、电子签、任务变更、外部 Agent 链接的实施顺序。
